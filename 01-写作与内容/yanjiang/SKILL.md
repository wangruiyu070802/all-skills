# 演讲/分享稿打磨工具

## 定位边界

- **本 Skill 处理**：分享、教学、复盘、启发、个人品牌直播
- **不处理**：销讲（成交导向的直播用 xiaojiang skill）
- **判断标准**：这场核心目标是"卖东西"→ xiaojiang；其他所有 → 本 skill

## 模式识别

| 用户意图 | 模式 | 关键词 |
|---------|------|--------|
| 从零准备分享 | 建稿 | "写分享稿""帮我准备""下周要直播" |
| 有草稿要优化 | 打磨 | "帮我打磨""优化""梳理""加钉子句" |
| 复盘已完成的分享 | 诊断 | "帮我诊断""打个分""这个分享怎么样" |

识别模式后执行对应工作流。判断不了就直接问用户。

## 底层四原则

1. **一个核心信息**（TED）：一场分享只服务一个想法。听众离场后能一句话转述
2. **认知负荷 4±1**：核心模块不超过 3-4 个
3. **峰终定律**：人只记住情绪最高峰和结尾。必须刻意设计这两个时刻
4. **间隔重复**：核心信息至少出现 3 次——开头预告、中间展开、结尾收束

## 时长适配

不同时长是完全不同的物种，骨架必须适配：

| 时长 | 模块数 | 特殊设计 |
|------|--------|---------|
| ≤20min | 2-3 | 紧凑，无中场休息，一个核心打透 |
| 30-60min | 3-4 | 可加1次中场互动/休息 |
| 60-120min | 分上下半场，每半场2-3模块 | 必须有中场休息，上下半场各有峰值时刻 |
| >120min | 分3章，每章2-3模块 | 每30-40分钟一个互动/休息节点 |

**长时长规则**（>60min）：
- 上半场偏"道法"（为什么），下半场偏"术器"（怎么做）
- 每半场都要有独立的钉子句和峰值时刻
- 中场休息前用一句悬念句拉住注意力

## 骨架结构

```
一、锚点开场（60秒）← 必选
   好奇心缺口 + 结构地图 + 时间承诺

二、核心模块 × 2-4 个 ← 模块内节奏见下方三种模板
   模块之间有明确过渡句

三、峰值时刻 × 1（长时长每半场各1个）← 必选

四、收束结尾（60秒）← 必选，不可即兴
   回扣核心 + 钉子句 + 行动指令
   结尾设计参考 [references/closings.md](references/closings.md)
```

## 模块内节奏（三种模板，按内容选）

不是每个知识点都适合同一种节奏。根据内容类型选：

### 模板A："讲→扎→给"（适合教方法、纠正误解）
- **讲**（30s）：平静说概念/框架
- **扎**（30s）：指出听众痛点，制造"这说的就是我"
- **给**（30s）：可操作的方法 + 钉子句收束

### 模板B："故事→洞察→行动"（适合分享经历、案例复盘）
- **故事**（60s）：讲一个具体的人/事/场景，有细节
- **洞察**（30s）：从故事中提炼出反直觉的规律
- **行动**（30s）：听众可以照做的一步 + 钉子句

### 模板C："数据→反直觉→方法"（适合打破认知、传递新信息）
- **数据**（20s）：一个让人"卧槽"的数字或事实
- **反直觉**（40s）：为什么大多数人理解错了
- **方法**（30s）：正确的做法 + 钉子句

每个模块选最适合的模板，一场分享可以混用不同模板。

## 钉子句设计

每个模块必须有一句。详细公式和范例见 [references/nail-sentences.md](references/nail-sentences.md)

四种基本公式：
- 对比反转："X 不是 Y，是 Z"
- 空间比喻："X 让你进门，但进门不等于上桌"
- 极简定义："助理是功能，合伙人是身份"
- 数字对比："稚嫩的人从 80 降到 20，成熟的人从 20 升到 80"

## 节奏："3-7-10"能量法

- **3**：平静叙述（蓄力）→ **7**：正常讲解（常态）→ **10**：峰值（最重要的话）
- 核心观点前降低能量 2-3 秒 → 短句 + 停顿钉住

## 建稿模式

**快速通道**：如果用户一句话里已包含主题+听众+时长，直接跳到第2步，不逐个追问。

1. **诊断**（缺什么问什么，不机械问满）：什么主题？对谁讲？多长时间？你最想让他们记住的一件事？
2. **提炼核心信息**：精炼成一句话（≤20 字）
3. **设计骨架**：根据时长适配规则确定结构，每模块选最合适的节奏模板（A/B/C）
4. **设计钉子句**：每模块一句
5. **设计峰值时刻**：确定位置和内容
6. **设计开头结尾**：开头参考 [references/openings.md](references/openings.md)，结尾参考 [references/closings.md](references/closings.md)
7. **输出大纲** → 过自检清单

## 打磨模式

1. 读取草稿/大纲/思维导图
2. 快速诊断：点出最大 2-3 个问题
3. 提炼/确认核心信息
4. 重组骨架 + 补钉子句 + 补过渡句
5. 标注节奏（⚡标记）
6. 过自检清单 → 输出优化大纲

## 诊断模式

1. 读取逐字稿
2. 10 维度打分（1-10）。评分标准见 [references/scoring.md](references/scoring.md)
3. 总分 + 最弱 3 个维度
4. 每个弱项：原文问题段落 → 改写示范（改前 vs 改后）
5. **重构骨架**：如果这场重新讲，骨架应该长什么样？输出一份完整的优化大纲（用默认输出格式）
6. 优先训练建议（按杠杆排序）

## 语感约束

1. 口语化，句子 ≤ 20 字
2. 数字代替形容词
3. 类比翻译抽象概念
4. 核心信息全场 ≥ 3 次
5. 每 5-8 分钟一个互动（线上直播）
6. 同一观点禁止连续 > 2 分钟不换角度
7. 过渡句明确

## 自检清单

输出前自动检查，不合格自动修正：

- [ ] 核心信息 ≤ 20 字？
- [ ] 模块 ≤ 4 个？
- [ ] 每模块有钉子句？
- [ ] 开头有好奇心缺口 + 结构地图？
- [ ] 结尾有回扣 + 钉子句 + 行动指令？
- [ ] 峰值时刻已设计并标注位置？
- [ ] 无连续 > 2 分钟同一观点？
- [ ] 过渡句明确？
- [ ] 互动间隔 ≤ 8 分钟？
