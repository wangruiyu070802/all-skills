# Writing Agent Prompt

帮助用户迭代优化写作智能体的系统提示词。

## 工作流程

```
用户请求 → 判断任务类型
                ↓
    ┌──────────┼──────────┐
    ↓          ↓          ↓
  创建新     分析诊断    优化迭代
  提示词     现有提示词   现有提示词
    ↓          ↓          ↓
收集需求   识别问题    收集反馈
    ↓          ↓          ↓
生成初版   给出建议    针对性改进
    ↓          ↓          ↓
    └──────────┴──────────┘
                ↓
           输出结果
```

## 创建新提示词

当用户需要从零创建写作 Agent 提示词时：

### 1. 收集关键信息

询问用户以下关键问题：
- **写作类型**：文章、邮件、报告、创意写作、营销文案、技术文档？
- **目标受众**：专业人士、普通读者、特定行业？
- **风格要求**：正式/非正式、简洁/详细、专业/通俗？
- **输出格式**：长度限制、结构要求、特殊格式？
- **约束条件**：禁止的内容、必须包含的元素？

### 2. 提示词结构模板

```markdown
# 角色定义
你是一个 [具体角色]，专注于 [核心能力]。

# 核心能力
- [能力1]
- [能力2]
- [能力3]

# 写作风格
- 语气：[正式/友好/专业/...]
- 结构：[清晰分段/层次分明/...]
- 特点：[简洁明了/详尽深入/...]

# 输出格式
[描述期望的输出结构]

# 约束条件
- 必须：[必要要求]
- 禁止：[需避免的内容]

# 工作流程
1. [步骤1]
2. [步骤2]
3. [步骤3]
```

### 3. 示例：技术博客写作 Agent

```markdown
# 角色定义
你是一位资深技术博客作者，擅长将复杂技术概念转化为易懂的文章。

# 核心能力
- 深入浅出地解释技术概念
- 提供实用的代码示例
- 结合实际应用场景

# 写作风格
- 语气：专业但友好，避免过度学术化
- 结构：标题层次清晰，代码与文字交替
- 特点：注重实践，每个概念配有示例

# 输出格式
1. 引言（问题背景）
2. 核心概念解释
3. 代码示例与解析
4. 最佳实践
5. 总结与延伸阅读

# 约束条件
- 必须：包含可运行的代码示例
- 禁止：使用未经解释的专业术语
```

## 分析诊断提示词

当用户提供现有提示词需要分析时：

### 诊断清单

| 维度 | 检查点 | 常见问题 |
|------|--------|----------|
| 角色定义 | 是否明确具体？ | 太笼统、缺乏特色 |
| 能力边界 | 是否清晰界定？ | 范围过大或过小 |
| 风格指导 | 是否可执行？ | 描述模糊、相互矛盾 |
| 输出格式 | 是否有明确标准？ | 缺少结构要求 |
| 约束条件 | 是否完整合理？ | 过严或过松 |

### 分析报告模板

```markdown
## 提示词分析报告

### 优点
- [识别出的优点]

### 问题诊断
1. **[问题类别]**：[具体描述]
   - 影响：[对输出的影响]
   - 建议：[改进方向]

### 改进优先级
1. [高优先级改进]
2. [中优先级改进]
3. [低优先级改进]
```

## 优化迭代提示词

当用户根据使用反馈需要优化时：

### 1. 收集反馈信息

- **实际输出示例**：用户提供 Agent 的实际输出
- **期望输出**：用户的预期是什么
- **差距描述**：哪里不符合预期

### 2. 常见问题与解决方案

**问题：输出太长/太短**
```diff
# 约束条件
- - 输出完整内容
+ - 输出控制在 500-800 字
+ - 重点内容优先，次要内容精简
```

**问题：风格不一致**
```diff
# 写作风格
- - 语气：专业
+ - 语气：专业但亲切，使用第二人称"你"
+ - 每段开头使用主动语态
+ - 避免被动句式和长难句
```

**问题：缺乏结构**
```diff
# 输出格式
+ 严格按以下结构输出：
+ 1. **概述**（1-2句话）
+ 2. **要点**（3-5个要点，每个不超过2句）
+ 3. **总结**（1句话行动建议）
```

**问题：内容偏离主题**
```diff
# 约束条件
+ - 每段内容必须直接关联用户问题
+ - 不要引入用户未提及的话题
+ - 如需补充背景，限制在1-2句
```

### 3. 迭代记录

建议用户维护版本记录：

```markdown
## 版本历史

### v1.2 (当前)
- 修改：增加字数限制
- 修改：明确段落结构
- 效果：输出更加精简，结构更清晰

### v1.1
- 修改：调整语气为更友好
- 效果：用户反馈更易读

### v1.0
- 初始版本
```

## 最佳实践

### 提示词设计原则

1. **具体优于模糊**："使用简短句子，每句不超过20字" 优于 "写得简洁"
2. **示例优于描述**：提供期望输出的示例比描述效果更好
3. **分层次定义**：从角色→能力→风格→格式→约束，逐层细化
4. **可测试性**：每个要求都应该能够被验证

### 避免的常见错误

- ❌ 角色定义过于宽泛："你是一个全能写手"
- ❌ 相互矛盾的要求："简洁" + "详尽解释每个细节"
- ❌ 缺乏具体标准："写得好一点"
- ❌ 过度约束：限制太多导致输出僵化
