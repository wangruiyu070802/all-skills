# AI方法学习器

从别人的AI使用素材（播客逐字稿、提示词、文章等）中提炼方法论，然后转化为你能直接用的东西。

**核心闭环：看到 → 提炼 → 确认需求 → 生成可用产出**

---

## Phase 1：提炼

### 第零步：判断输入类型

用户提供素材后，先判断是哪种类型：

| 类型 | 特征 | 处理流程 |
|------|------|---------|
| **播客/访谈逐字稿** | 对话形式，信息密集，包含实战经验 | [workflow/podcast-extraction.md](workflow/podcast-extraction.md) |
| **提示词/Prompt** | 结构化文本，包含具体指令和技巧 | [workflow/prompt-analysis.md](workflow/prompt-analysis.md) |
| **文章/教程** | 系统化内容，有框架和步骤 | [workflow/article-learning.md](workflow/article-learning.md) |

如果不确定，问用户："这是什么类型的素材？从哪里来的？"

### 执行提炼

根据输入类型，选择对应的工作流执行提炼。提炼完成后，**不要直接输出文档就结束**，必须进入 Phase 2。

---

## Phase 2：学以致用（核心环节）

> 提炼不是终点，用起来才是。

### Step 1：推荐应用场景

提炼完成后，结合用户背景（读取 TELOS 文件：skills.md、projects.md、goals.md），推荐 2-3 个具体的应用场景。

**输出格式：**

```
我从这个素材里提炼了 [N] 个核心方法：
1. [方法名]：[一句话说明]
2. [方法名]：[一句话说明]

结合你现在在做的事，我觉得可以这样用：

场景A：[具体场景] — 用方法[X]
  → 比如：[举一个具体例子]

场景B：[具体场景] — 用方法[Y]
  → 比如：[举一个具体例子]

场景C：[具体场景] — 用方法[Z]（如果有的话）
  → 比如：[举一个具体例子]

你想用在哪个场景？还是有别的想法？
```

**推荐场景的原则：**
- 从用户当前最高优先级的项目/任务出发，不要推荐和用户无关的场景
- 场景要具体到「用在哪个环节、怎么用」，不能是「可以提升效率」这种废话
- 如果提炼的方法和用户现有的某个 skill 直接相关，优先推荐升级那个 skill

### Step 2：等用户确认

**关键：这一步必须等用户回复，不能自己跳过。**

用户可能的回复类型：
- 选了某个场景 → 进入 Step 3
- 说「都试试」 → 按优先级依次生成
- 提出新的应用场景 → 按用户说的来
- 说「先记着」 → 保存提炼结果，跳过产出生成（走旧的存档流程）

### Step 3：生成可直接用的产出

根据用户选择的场景，生成对应的可执行产出：

| 应用方式 | 生成什么 | 说明 |
|---------|---------|------|
| **升级现有 skill** | 修改 skill 文件的具体 diff | 直接告诉用户改哪里、怎么改，用户确认后执行 |
| **创建新 prompt** | 完整的、可直接粘贴使用的 prompt | 不是模板，是填好了的、针对用户场景的完成品 |
| **改进工作流** | 工作流的调整建议 + 具体操作步骤 | 精确到「在哪个步骤加什么」 |
| **创建新 skill** | 调用 skill-creator 生成 | 只在方法足够完整、值得反复用时才建议 |
| **融入 CLAUDE.md** | 写入经验规则的具体条目 | 适合通用性强的认知/原则类方法 |

**产出的质量标准：**
- 用户拿到就能直接用，不需要再改
- 如果需要用户补充信息才能生成，先问清楚再生成
- 生成后问一句：「试一下，看看效果怎么样？要调整吗？」

## 完成标志

一次完整的学习闭环 = 以下三项都完成：

1. **提炼了核心方法**（Phase 1 输出）
2. **和用户确认了应用场景**（Phase 2 Step 2）
3. **生成了可直接用的产出**（Phase 2 Step 3）

只完成 Phase 1 不算完成。除非用户明确说「先记着不用」。
