# 项目：投流帖改编迭代工程

## 1. 项目目标

通过人机协作，以文件夹作为"外部记忆"，持续迭代优化投流帖改编规则。本项目旨在建立一个标准化的、可复现的、可审计的投流帖改编工作流。

## 2. 文件夹结构约定

| 路径 | 用途 |
|:---|:---|
| `SKILL.md` | **（本文件）** 项目的唯一说明书，定义了所有目标、约定和 Skill。 |
| `1_prompts/v{n}.md` | 第 n 版改编规则。 |
| `2_outputs/v{n}/output_xx.md` | 第 n 版规则生成的改编产出。 |
| `3_feedback/v{n}_feedback.md` | 人类对第 n 版产出的反馈（产出原文+批注）。 |
| `golden_rules.md` | 从所有反馈中提炼的永久性规则，每次改编必须遵守。 |

## 3. Skills

你（Claude Code）的角色是这个项目的"流程管理员"。当收到以下 Skill 触发词时，请严格按照对应的动作执行。

---

### Skill 1：初始化项目

- **触发词**：`初始化项目`
- **动作**：
    1. **先检查项目是否已存在**：扫描 `1_prompts/` 文件夹，如果发现任何 `v*.md` 文件，立即停止并警告用户："检测到已有版本数据，拒绝初始化以避免覆盖。如需查看状态请说「当前状态」。"
    2. 创建 `1_prompts/`、`2_outputs/`、`3_feedback/` 文件夹（如不存在）。
    3. 创建 `1_prompts/v1.md` 文件，写入初始版改编规则。
    4. 创建空的 `golden_rules.md` 文件。
    5. 向用户报告："项目已初始化。V1 版改编规则已就绪。请说「改编投流帖」开始使用。"

---

### Skill 2：改编投流帖

- **触发词**：`投流帖`、`投流帖改编`、`留学求职投流帖`、`改编投流帖`
- **动作**：
    1. 在 `1_prompts/` 文件夹中找到版本号最高的规则文件（例如 `v1.md`）。
    2. 读取该规则内容，基于它执行改编任务。
    3. 询问用户发送竞品投流帖的图片和文案原文。
    4. 识别图片中的所有文字，分析原帖结构。
    5. 按照规则改编文案和图片，遵循原则：**能不改就不改，只改必须改的**。
    6. 输出完整方案：
       - 一、设计师改动清单（按图片逐张输出）
       - 二、文案（直接复制）
    7. 在 `2_outputs/v{n}/` 下保存产出为 `output_01.md`（如已存在则递增编号）。
    8. 创建或更新反馈模板文件 `3_feedback/v{n}_feedback.md`，将产出内容按以下格式写入：
        ```markdown
        ## 产出 output_xx.md

        ### 改编方案：
        > [产出原文]

        ### 您的反馈：
        （请在此处填写您的反馈）

        ---
        ```
    9. 向用户报告："产出已生成：`2_outputs/v{n}/output_xx.md`。请在 `3_feedback/v{n}_feedback.md` 中填写您的反馈。完成后请说「开始迭代」。"

---

### Skill 3：开始迭代

- **触发词**：`开始迭代`、`根据反馈迭代`
- **动作**：

    **第一阶段：评估（迭代管家）**

    1. 确定当前最新版本号 `n`。
    2. 通读以下所有材料：
        - `1_prompts/v{n}.md`（当前版本改编规则）
        - `2_outputs/v{n}/` 下的所有产出
        - `3_feedback/v{n}_feedback.md`（当前版本反馈）
        - `golden_rules.md`（所有历史规则）
    3. 用你的智力综合评判：**"基于目前的信息，现在进行迭代，是否能有效推进项目？"**
        - 反馈是否足够清晰、具体、可操作？
        - 反馈是否指向了真正的问题？
        - 是否存在反馈之间的矛盾或与 golden_rules 的冲突？
        - 是否需要更多产出样本来验证？
        - 现在迭代能否真正解决问题，还是可能走弯路？
    4. 给出你的判断：
        - **如果可以迭代**：说明理由，询问用户"是否确认执行迭代？"
        - **如果建议暂缓**：说明顾虑，给出具体建议（如"建议先补充更多反馈"或"请澄清以下冲突点"）

    **第二阶段：执行（需用户确认后）**

    5. **学习与提炼**：
        - 从反馈中识别具有普适性的规则。
        - 将新规则追加到 `golden_rules.md`，附上来源版本。
    6. **重构与生成**：
        - 创建 `1_prompts/v{n+1}.md`。
        - 以旧版为基础，结合所有反馈和黄金法则，进行外科手术式的修改。
    7. **生成反馈模板**：
        - 创建 `3_feedback/v{n+1}_feedback.md`。
    8. **交付**：
        - 向用户报告迭代结果，提示："新版规则已生成：`1_prompts/v{n+1}.md`。请说「改编投流帖」使用新版规则。"

---

### Skill 4：查看状态

- **触发词**：`当前状态`、`汇报进度`
- **动作**：
    1. 扫描 `1_prompts/` 文件夹，确定最新版本号 `n`。
    2. 检查 `3_feedback/v{n}_feedback.md` 是否存在及填写状态。
    3. 统计 `golden_rules.md` 中的规则数量。
    4. 向用户报告：
        - 最新改编规则版本：V{n}
        - V{n} 反馈状态：[已填写 / 待填写]
        - 黄金法则总数：[数量]
        - 下一步建议：[根据状态给出建议]

## 5. 重要约束

- 你必须严格遵守本文件定义的 Skill 和动作，不要即兴发挥。
- 所有文件操作都必须在当前工作目录下进行。
- 禁止删除任何历史版本的规则或 feedback 文件，以保证迭代过程的可追溯性。
- 在执行任何 Skill 前，都应首先回顾本文件的内容，确保你的行为符合约定。
- "开始迭代" Skill 必须先评估、获得用户确认后才能执行，不可跳过评估阶段。
- 每次改编前，先读取 `golden_rules.md`，确保遵守所有规则。
