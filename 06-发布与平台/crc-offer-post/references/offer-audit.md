# Offer审查机制

生成内容前，必须先完成以下审查，确保offer信息无逻辑漏洞。

---

## 审查流程

```
收到offer信息/截图
      ↓
【第一步】提取关键信息
      ↓
【第二步】逐项审查（见下方清单）
      ↓
  发现问题 → 输出审查报告，暂停，等用户确认
  无问题   → 继续生成内容
```

---

## 审查清单

### 1. 公司信息一致性 ⚠️

- 截图中的公司名 vs 用户提供的公司名是否一致
- 公司Logo是否与公司名匹配
- 邮件发件人域名是否与公司匹配

**常见易混淆公司：**

| 名称变体 | 是否同一家 |
|---------|-----------|
| JPMorgan / J.P. Morgan / 摩根大通 | ✅ 同一家 |
| Morgan Stanley / 摩根士丹利 | ✅ 同一家 |
| JPMorgan ≠ Morgan Stanley | ⚠️ 不同公司！ |
| Citi / Citibank / Citigroup / 花旗 | ✅ 同一家 |
| UBS / 瑞银 | ✅ 同一家 |
| Deutsche Bank / 德意志银行 | ✅ 同一家 |

### 2. 时间线合理性 ⚠️

- Offer发出时间 vs 实习/入职时间是否合理
- 学生年级 vs 实习类型是否匹配

**时间线速查表：**

| 实习类型 | 正常Offer时间 | 实习开始时间 |
|---------|-------------|------------|
| 2027暑期实习 | 2025秋-2026春 | 2027年6-8月 |
| 2026暑期实习 | 2024秋-2025春 | 2026年6-8月 |
| 全职 | 实习结束后或校招季 | 毕业后 |

### 3. 部门/职位一致性 ⚠️

- 截图中的部门名 vs 用户提供的部门名是否一致
- 职位级别是否合理（Analyst/Associate/Intern）

**常见部门缩写：**

| 缩写 | 全称 |
|------|------|
| IBD | Investment Banking Division 投行部 |
| S&T | Sales & Trading 销售交易部 |
| PWM | Private Wealth Management 私人财富管理 |
| AM | Asset Management 资产管理 |
| ER | Equity Research 股票研究 |
| GM | Global Markets 全球市场 |

### 4. 地点一致性 ⚠️

- 截图中的办公地点 vs 用户提供的地点是否一致
- 公司在该地点是否有对应部门

### 5. 其他低级错误 ⚠️

- 性别代词是否一致（他/她）
- 学校名称拼写是否正确
- 年份是否正确

| 问题类型 | 具体问题 | 严重程度 |
