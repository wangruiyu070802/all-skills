# Golden Rules

## 规则 1：最小化改动原则（来源：V1 反馈）

- **换皮仿写时，尽可能只替换人设相关部分，其他内容保持原样**
- 不要改动参考文章的结构、语言风格、核心观点
- 只替换：身份、经历、学校、公司、时间、数字等人设相关细节
- 例如：参考文章说"从公司内部跳槽做financial planning"，应改为"从Amazon跳去做量化"，而不是重写整个开头

## 规则 2：反馈模板简化（来源：V1 反馈）

- **反馈文件中不需要重复输出产出原文**
- 只需提供产出文件路径的引用
- 让用户直接填写反馈即可

## 规则 3：对比表格位置（来源：V2 反馈）

- **参考文章 vs 改编文章的逐句对比表格应放在 output 文件中**
- feedback 文件只保留基本信息和反馈区域
- 让用户能直接在 feedback 文件中填写反馈，无需滚动过长的对比表格

## 规则 4：强制输出对比表格（来源：V3 反馈）

- **每次产出必须包含「参考文章 vs 改编文章」的逐句对比表格**
- 清晰标出每处换皮改动，让用户一目了然看到哪些内容被替换了
- 对比表格放在产出文件的末尾

## 规则 5：人设经历多样化，禁止每篇都用同一个点（来源：V4 反馈）

- **同一个人设的不同帖子，不能每篇都强调同一段核心经历**
- 例如 Michelle 不能每篇都说"从麦肯锡出来换赛道"，Jason 不能每篇都说"从Amazon跳槽到量化"
- 人设档案里有多个可用素材（公司、数字、经历片段），每次应**轮换使用不同的切入点**
- 纯干货帖（如政策攻略）可以只用服务数据（"帮了300多个学生"）做软植入，不必强行嵌入个人转型故事
- 原则：读者连续看3篇不应该觉得「又是这个开头」

## 规则 6：引号统一使用「」（来源：V4 反馈）

- **产出正文中所有引号统一使用中文直角引号「」，禁止使用英文双引号""**
- 嵌套引号使用『』
- 英文术语、品牌名等不需要引号的场景照常处理
