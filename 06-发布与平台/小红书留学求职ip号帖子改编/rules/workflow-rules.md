# 工作流规则

小红书素人文智能体迭代工程的核心规则和约束。

---

## 核心约束

### 1. 严格遵守定义的 Skill 和动作

- 不要即兴发挥
- 按照 SKILL.md 中定义的流程执行
- 每个 Skill 都有明确的触发词和动作

### 2. 所有文件操作在当前工作目录下进行

- 不要在其他目录创建文件
- 保持文件夹结构的一致性

### 3. 禁止删除任何历史版本文件

- 保证可追溯性
- 所有 prompt、output、feedback 都要保留
- 版本号只增不减

### 4. "开始迭代" 必须先评估、获得确认后才能执行

- 第一阶段：评估（自动）
- 第二阶段：执行（需用户确认）
- 不要跳过评估阶段

## 文件命名规范

### Prompt 文件

- 格式：`1_prompts/v{n}.md`
- 版本号从 1 开始递增
- 例如：v1.md, v2.md, v3.md

### 产出文件

- 格式：`2_outputs/v{n}_output_{xx}.md`
- 扁平化命名，不分子文件夹
- 例如：v1_output_01.md, v1_output_02.md

### 反馈文件

- 格式：`3_feedback/v{n}_feedback.md`
- 每个版本一个反馈文件
- 只写引用路径，不复制产出全文

### 人设文件

- 格式：`0_personas/persona_{名称}.md`
- 例如：persona_Jason.md, persona_Michelle.md

### 范例文件

- 好范例：`4_examples/good_example_{xx}.md`
- 差范例：`4_examples/bad_example_{xx}.md`

## 质量标准

### 换皮仿写的要求

**必须保留：**
- 整体结构和段落逻辑
- 语言风格和口吻
- 核心观点和方法论
- 情绪节奏和转折

**必须替换：**
- 人设相关的身份信息
- 具体的经历和数字
- 细节和案例
- 与人设不符的内容

### 反馈的要求

**好的反馈：**
- 具体（引用具体位置）
- 可操作（说明如何改进）
- 有理由（说明为什么要改）

**不好的反馈：**
- 模糊（"不太好"、"有点怪"）
- 不可操作（"要写得更好"）
- 没有理由（只说结论不说原因）
