# 项目：留学求职赛道小红书素人文智能体迭代工程

## 1. 项目目标

通过人机协作，以文件夹作为"外部记忆"，持续迭代优化一个能写出高质量**留学求职赛道小红书素人文**的智能体 System Prompt。

## 2. 文件夹结构约定

| 路径 | 用途 |
|:---|:---|
| `CLAUDE.md` | **（本文件）** 项目的唯一说明书，定义了所有目标、约定和 Skill。 |
| `0_personas/` | **人设库**，存放不同账号的人设定义文件。 |
| `1_prompts/v{n}.md` | 第 n 版 System Prompt。 |
| `2_outputs/v{n}_output_xx.md` | 第 n 版 prompt 生成的产出（扁平化命名，不分子文件夹）。 |
| `3_feedback/v{n}_feedback.md` | 人类对第 n 版产出的反馈（产出原文+批注）。 |
| `4_examples/` | **范例库**，存放好范例和差范例（独立于 prompt，按需读取）。 |
| `golden_rules.md` | 从所有反馈中提炼的永久性规则，每次迭代必须遵守。 |

## 3. Skills

你（Claude）的角色是这个项目的"流程管理员"。当收到以下 Skill 触发词时，请严格按照对应的动作执行。

---

### Skill 1：初始化项目

- **触发词**：`初始化项目`
- **动作**：
    1. 创建 `0_personas/`、`1_prompts/`、`2_outputs/`、`3_feedback/`、`4_examples/` 文件夹（如不存在）。
    2. 创建 `1_prompts/v1.md` 文件，写入初始版 System Prompt。
    3. 创建 `golden_rules.md` 文件，写入初始规则。
    4. 向用户报告："项目已初始化。V1 版 System Prompt 已就绪。请先用「添加人设」创建一个人设，再用「生成产出」让智能体写素人文。"

---

### Skill 2：生成产出

- **触发词**：`生成产出` / `写一篇素人文`
- **动作**：
    1. 在 `1_prompts/` 文件夹中找到版本号最高的 prompt 文件，读取内容。
    2. **询问用户选择人设**：列出 `0_personas/` 中的所有人设，让用户选择本次使用哪个人设。
    3. **询问用户提供参考文章**：请用户粘贴一篇参考文章（作为风格和内容框架的模板）。
    4. **换皮仿写**：基于 prompt 的写作规范，将参考文章中的人设相关部分（身份、经历、数字、细节等）替换为指定人设的信息，生成新文章。保留参考文章的：
        - 整体结构和段落逻辑
        - 语言风格和口吻
        - 核心观点和方法论
        - 情绪节奏和转折
    5. 将产出保存为 `2_outputs/v{n}_output_01.md`（扁平化命名，如已存在则递增编号）。
    6. 创建或更新 `3_feedback/v{n}_feedback.md`（反馈文件只写引用路径，不复制产出全文）：
        ```markdown
        # V{n} 版本反馈

        ---

        ## 产出 v{n}_output_xx.md
        **使用人设**：{人设名称}
        **参考文章**：[参考文章标题或前20字]
        **对应产出**：`2_outputs/v{n}_output_xx.md`

        ### 您的反馈：
        （请引用具体位置，如「第3段」「开头那句」，填写您的反馈）

        ---
        ```
    7. 向用户报告："产出已生成。请在 `3_feedback/v{n}_feedback.md` 中填写您的反馈。完成后请说「开始迭代」。"

---

### Skill 3：开始迭代

- **触发词**：`开始迭代` / `根据反馈迭代`
- **动作**：

    **第一阶段：评估**
    
    1. 确定当前最新版本号 `n`。
    2. 通读以下所有材料：
        - `1_prompts/v{n}.md`（当前版本 Prompt）
        - `2_outputs/v{n}_output_*.md`（当前版本所有产出）
        - `3_feedback/v{n}_feedback.md`（当前版本反馈）
        - `golden_rules.md`（所有历史规则）
    3. 综合评判：**"基于目前的信息，现在进行迭代，是否能有效推进项目？"**
        - 反馈是否足够清晰、具体、可操作？
        - 是否存在反馈之间的矛盾或与 golden_rules 的冲突？
        - 是否需要更多产出样本来验证？
    4. 给出判断：
        - **如果可以迭代**：说明理由，询问"是否确认执行迭代？"
        - **如果建议暂缓**：说明顾虑，给出具体建议。

    **第二阶段：执行（需用户确认后）**
    
    5. **学习与提炼**：从反馈中识别具有普适性的规则，追加到 `golden_rules.md`。
    6. **重构 Prompt**：创建 `1_prompts/v{n+1}.md`，以旧版为基础进行外科手术式修改。
    7. **生成新版产出**：基于新版 prompt 生成一篇素人文，保存到 `2_outputs/v{n+1}_output_01.md`。
    8. **生成反馈模板**：创建 `3_feedback/v{n+1}_feedback.md`。
    9. **交付**：向用户报告迭代结果，提示填写新版反馈。

---

### Skill 4：查看状态

- **触发词**：`当前状态` / `汇报进度`
- **动作**：
    1. 扫描文件夹，确定最新版本号 `n`。
    2. 检查 `3_feedback/v{n}_feedback.md` 的填写状态。
    3. 统计 `golden_rules.md` 中的规则数量。
    4. 统计 `0_personas/` 中的人设数量。
    5. 向用户报告：
        - 最新 Prompt 版本：V{n}
        - V{n} 产出数量：[数量]
        - V{n} 反馈状态：[已填写 / 待填写]
        - 黄金法则总数：[数量]
        - 人设库：[列出所有人设名称]
        - 下一步建议：[根据状态给出建议]

---

### Skill 5：添加人设

- **触发词**：`添加人设` / `新建人设`
- **动作**：
    1. 询问用户提供以下信息：
        - 人设名称（如：Jason、素人小A）
        - 身份定位（如：UIUC毕业的北美求职博主）
        - 核心经历（如：22年秋招拿到5个offer包括Amazon）
        - 说话风格（如：专业但接地气，偶尔自嘲）
        - 可以提的真实细节（学校、公司、时间、数字）
        - 不能说的内容（与人设冲突的信息）
    2. 生成人设文件，保存到 `0_personas/persona_{名称}.md`。
    3. 向用户报告："人设「{名称}」已创建。生成产出时可以选择使用此人设。"

---

### Skill 6：查看人设

- **触发词**：`查看人设` / `人设列表`
- **动作**：
    1. 列出 `0_personas/` 文件夹中所有人设文件。
    2. 简要展示每个人设的核心信息（名称、身份定位、核心经历）。

---

### Skill 7：添加范例

- **触发词**：`添加好范例` / `添加差范例` / `更新范例`
- **动作**：
    1. 询问用户：这是一篇**好范例**还是**差范例**？
    2. 接收用户提供的文案内容。
    3. **如果是好范例**：
        - 对文案进行详细分析（结构、话术、风格、为什么好）
        - 保存到 `4_examples/good_example_xx.md`（包含原文和分析）
        - 在当前最新版 prompt 的「好范例」部分添加引用：`参见 4_examples/good_example_xx.md`
    4. **如果是差范例**：
        - 分析问题出在哪里（哪些地方不对、为什么不对）
        - 保存到 `4_examples/bad_example_xx.md`（包含原文和分析）
        - 在当前最新版 prompt 的「差范例」部分添加引用：`参见 4_examples/bad_example_xx.md`
    5. 向用户报告："范例已保存到 `4_examples/`，并在 V{n} 的 Prompt 中添加了引用。"

## 5. 重要约束

- 严格遵守本文件定义的 Skill 和动作，不要即兴发挥。
- 所有文件操作都在当前工作目录下进行。
- 禁止删除任何历史版本的 prompt 或 feedback 文件，保证可追溯性。
- "开始迭代" Skill 必须先评估、获得用户确认后才能执行。
